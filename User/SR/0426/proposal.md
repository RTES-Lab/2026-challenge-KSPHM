## 1. 문제 정의

### 1.1 과제 개요

산업 환경에서 운용 중인 베어링(30306)의 **잔여수명(Remaining Useful Life, RUL)**을 예측한다. 4채널 진동 센서(CH1~CH4, 25.6 kHz 샘플링)로 수집된 시계열 데이터를 입력으로 받아, 현재 시점에서 베어링이 고장나기까지 남은 시간(초)을 출력한다.

### 1.2 데이터 구성

| 항목       | 내용                                               |
| ---------- | -------------------------------------------------- |
| 데이터 형식 | `.tdms` 파일 (1분 길이 진동 신호)                   |
| 채널       | CH1 (전면 수직), CH2 (전면 수평), CH3 (후면 수직), CH4 (후면 수평) |
| 샘플링 주파수 | 25,600 Hz                                        |
| 측정 간격   | 10분 (= 파일 1개)                                  |
| 운전 조건   | 축 회전속도 700~950 RPM (변속 조건)                  |
| 학습 데이터  | Train1 ~ Train4 (수명 전체를 포함하는 완전 run)       |
| 테스트 데이터 | 수명 중간 지점까지만 제공, **운전 데이터(RPM) 없음**   |

### 1.3 핵심 도전과제

1. **타코미터 부재**: 테스트 데이터에 RPM 정보가 없어 회전속도를 직접 알 수 없다.
2. **변속 운전**: RPM이 700~950 범위에서 변동하므로, 고정 RPM 가정 기반의 주파수 분석은 부정확하다.
3. **비정상(non-stationary) 신호**: 열화 진행에 따라 진동 특성이 시간에 따라 변화한다.

## 3. 1단계: Tacholess 회전속도 추정 (GLCT-GWO)

### 3.1 왜 필요한가

진동 기반 베어링 고장 진단에서는 **결함 주파수(BPFI, BPFO, BSF, FTF)**를 분석하는 것이 핵심이다. 이 주파수들은 축 회전속도에 비례하므로, 정확한 진단을 위해서는 순간순간의 회전속도를 알아야 한다. 그러나 테스트 데이터에는 타코미터가 없으므로, **진동 신호 자체에서 회전속도를 추정**해야 한다.

### 3.2 GLCT (Generalized Linear Chirplet Transform)

기존 STFT(Short-Time Fourier Transform)는 일정한 주파수 성분만 잘 분석할 수 있다. 하지만 축 회전속도가 변동하면 주파수 성분이 시간에 따라 변하므로(chirp 신호), STFT로는 정확한 분석이 어렵다.

**GLCT**는 다양한 **chirp rate(주파수 변화율)**를 가진 기저함수로 신호를 분해한다:

```
GLCT(t, f) = max   |∫ x(τ) · w(τ-t) · e^{-j·c·(τ-t)²/2} · e^{-j2πfτ} dτ|
             α∈A
```

- `w(τ-t)`: 분석 윈도우 (Gaussian)
- `e^{-j·c·(τ-t)²/2}`: chirp demodulation (chirp rate `c = tan(α)`)
- 여러 각도 `α`에 대해 계산한 후, 각 (t, f) 지점에서 에너지가 **최대**인 chirp rate를 선택

이를 통해 **변속 운전 환경에서도 선명한 시간-주파수 표현**을 얻을 수 있다.

### 3.3 GWO (Grey Wolf Optimizer)로 파라미터 최적화

GLCT의 두 핵심 파라미터인 **윈도우 길이 L**과 **demodulator 수 N**을 **GWO(회색늑대 최적화)**로 자동 탐색한다. 기존 GLCT-SS가 Scale-space로 N만 결정했던 것과 달리, GLCT-GWO는 L과 N을 **동시에** 최적화한다.

**목적함수**: TF 평면의 **Gini index(GI)** 최대화

```
GI = 1 - 2 · Σ (x_n / ‖x‖₁) · ((N - n + 0.5) / N)    (x: 크기 오름차순 정렬)
```

- GI → 1: 에너지가 소수의 주파수 빈에 집중 = 선명한 ridge = 좋은 파라미터
- GI → 0: 에너지가 균일하게 퍼짐 = 흐린 TF 표현 = 나쁜 파라미터

**GWO 탐색 설정** (논문 기준):

| 파라미터 | 범위 | 기본값 |
|---|---|---|
| L (윈도우 길이) | [default/2, 3·default/2] | — |
| N (demodulator 수) | [1, 10] | — |
| 탐색 에이전트 | — | 20 |
| 최대 반복 횟수 Tmax | — | 60 |

> **비단조(non-monotonous) 변속에서의 장점**: GLCT-SS(Scale-space)는 단조 변속(가속 또는 감속만)에 적합하지만, GLCT-GWO는 복잡한 속도 변화 패턴에서도 L과 N을 동시에 최적화하므로 더 정확한 IRF를 추출한다 (논문 Table 4: inner fault에서 GLCT-GWO MAE 0.553 < GLCT-SS MAE 0.562).

### 3.4 IRF 추출

GLCT로 얻은 시간-주파수 평면에서 **ridge extraction**을 수행한다:

1. 축 주파수가 존재할 것으로 예상되는 대역(~10.8~17.5 Hz, 즉 650~1050 RPM)으로 제한
2. 각 시간 프레임에서 해당 대역 내 에너지가 최대인 주파수를 선택
3. Median 필터로 스무딩 → **순시 회전주파수 IRF(t)** 완성

### 3.5 Fallback 전략

GLCT-GWO가 실패하는 경우(노이즈가 심하거나 축 성분이 약한 경우), Welch PSD에서 해당 대역의 피크 주파수를 사용하는 **fallback**을 구현했다.

### 3.6 구현 최적화

GWO 최적화 루프(1200회 GLCT 평가) 속도를 위해 두 가지 기법을 적용했다:

1. **stride_tricks 기반 벡터화**: `sliding_window_view`로 프레임 추출 루프를 제거하여 모든 프레임을 한 번의 numpy FFT 연산으로 처리
2. **최적화 중 coarse hop**: GWO 탐색 시 5배 큰 hop으로 TF 계산(빠른 GI 평가), 최종 TF는 정밀한 hop으로 재계산

## 4. 2단계: 특성 추출

### 4.1 Angular Resampling (등각도 리샘플링)

일반적인 시간 영역 샘플링에서는 RPM이 변하면 한 회전당 샘플 수가 달라져 주파수 분석 결과가 번지게(smearing) 된다.

**Angular resampling**은 이를 해결한다:

1. IRF(t)를 시간에 대해 적분하여 **누적 각도 θ(t)**를 구한다
2. 시간 축 대신 **각도 축(등간격 각도)**으로 신호를 재샘플링한다
3. 결과적으로 **1회전 = 256 샘플**의 등각도 신호를 얻는다

이렇게 하면 RPM 변동과 무관하게, 결함 주파수가 항상 같은 **order(차수)**에 나타난다.

### 4.2 추출하는 특성들

`.tdms` 파일 1개 (1분 분량) → 4채널 × 아래 특성 → **1개의 행(row)**으로 변환

#### (A) 시간 도메인 통계 (채널당 9개)

| 특성           | 의미                                          |
| -------------- | --------------------------------------------- |
| RMS            | 전체 진동 에너지                              |
| Peak           | 최대 진폭 (충격 성분)                          |
| Std            | 표준편차                                       |
| Kurtosis       | 첨도 — 충격성 결함 민감 (정상: ~3, 결함: ↑)    |
| Skewness       | 왜도 — 비대칭 진동 패턴                        |
| Crest Factor   | Peak / RMS — 충격 대 평균 에너지 비            |
| Impulse Factor | Peak / Mean|x| — Crest의 변형                  |
| Shape Factor   | RMS / Mean|x| — 파형 형태                      |
| Margin Factor  | Peak / (Mean√|x|)² — 극단 충격 민감            |

#### (B) 결함 주파수 진폭 (채널당 18개)

베어링 30306의 결함 주파수(order 단위):

| 결함 유형                   | Order       | 의미                  |
| -------------------------- | ----------- | --------------------- |
| BPFI (내륜 결함 통과 주파수) | 8.40/rev   | 내륜에 결함이 있을 때  |
| BPFO (외륜 결함 통과 주파수) | 5.58/rev   | 외륜에 결함이 있을 때  |
| BSF (전동체 결함 주파수)     | 4.68/rev   | 볼에 결함이 있을 때    |
| FTF (보유기 결함 주파수)     | 0.40/rev   | 케이지에 결함이 있을 때 |

각 결함 주파수의 **1~3차 고조파**(h1, h2, h3) 진폭을 추출한다.
추가로 BPFI, BPFO의 **±1 order 사이드밴드**, BSF의 **±FTF 사이드밴드** 진폭도 추출한다.
→ 사이드밴드는 결함이 회전 운동과 결합될 때 나타나는 변조 성분이다.

추출 과정:
```
등각도 신호 → 밴드패스(10~100 orders) → Hilbert 변환(포락선)
→ Welch PSD → 결함 주파수 ± 0.1 order 윈도우 내 피크값
```

#### (C) 밴드 에너지 (채널당 4개)

| 밴드    | Order 범위 | 의미             |
| ------- | ---------- | ---------------- |
| E_low   | 0.5 ~ 3.0 | 저차 성분 에너지  |
| E_mid   | 3.0 ~ 7.0 | 중간 차수 에너지  |
| E_high  | 7.0 ~ 12.0 | 고차 성분 에너지 |
| E_vhigh | 12.0 ~ 20.0 | 초고차 에너지   |

#### (D) 축 회전 정보 (3개, 채널 공통)

- `shaft_hz`: IRF 중앙값 (Hz)
- `rpm_est`: 추정 RPM (= shaft_hz × 60)
- `shaft_std`: IRF 표준편차 (회전 안정성 지표)

#### 특성 총 개수

`4채널 × (9 시간도메인 + 12 결함주파수 + 6 사이드밴드 + 4 밴드에너지) + 3 축정보 = 127개`

### 4.3 HI (Health Index) 품질 평가

추출된 127개 특성 중 어떤 것이 베어링 열화를 잘 반영하는지를 정량적으로 평가했다. 3가지 평가 지표를 사용한다:

| 지표 | 정의 | 의미 |
|---|---|---|
| **Monotonicity (Mon)** | \|Σ sign(Δx)\| / (N-1) | 시간에 따른 단조 변화 정도. 1이면 완전 단조 |
| **Trendability (Tre)** | \|Spearman(시간, x)\| | 시간과의 상관 강도. 1이면 완벽한 추세 |
| **Prognosability (Pro)** | 1 - exp(-\|μ_late - μ_early\| / (σ_early + σ_late)) | 초기/말기 분포 분리도. 1이면 완전 분리 |
| **Composite** | (Mon + Tre + Pro) / 3 | 종합 점수 |

| 4 | BSF_sb_p | 0.406 | 0.097 | 0.601 | 0.520 |

| 6 | FTF_h3 | 0.392 | 0.071 | 0.603 | 0.501 |
| 7 | FTF_h1 | 0.384 | 0.057 | 0.574 | 0.523 |

## 5. 3단계: Adaptive MAGNN-TCN 모델

### 5.1 모델 선택 배경

베어링 열화는 단일 특성으로 포착하기 어렵고, **여러 특성(변수) 간의 상호작용**과 **시간적 패턴**을 동시에 모델링해야 한다. Adaptive MAGNN-TCN은:

- **다변량 그래프 신경망(GNN)**으로 변수 간 관계를 학습하고
- **다중 스케일(Multiscale)**로 다양한 시간 해상도의 패턴을 포착하며
- **TCN(Temporal Convolutional Network)**으로 장기 시간 의존성을 모델링한다

### 5.2 입력 구성

학습 시 각 시점 `i`에서 과거 **16개 프레임**의 특성 벡터를 묶어 하나의 입력으로 만든다 (슬라이딩 윈도우):

```
입력 X: (배치, N_vars=127, T=16)
         ↑              ↑
         특성 개수       윈도우 길이 (= 160분 분량)
```

초기 프레임에서 과거 데이터가 부족하면 **zero-padding**으로 채운다.

### 5.3 모델 아키텍처

```
입력 (B, 127, 16)
     │
     ▼
┌────────────────────────────────────────────┐
│ Multiscale Pyramid (3-scale)               │
│  Scale 1: 1×1 Conv + Stride-2 Conv → T=8  │
│  Scale 2: 1×1 Conv + Stride-2 Conv → T=4  │
│  Scale 3: 1×1 Conv + Stride-2 Conv → T=2  │
└────────────┬───────────────────────────────┘
             │ 3개의 스케일별 특성 맵
     ┌───────┼───────┐
     ▼       ▼       ▼
┌─────────────────────────────────────────────┐
│ AGL (Adaptive Graph Learning)               │
│  • 노드 임베딩 E_nodes (127×16)             │
│  • 스케일 임베딩 E_scale (3×16)             │
│  • 스케일별 인접행렬 A_k 생성               │
│  • Top-K 희소화 (k=12) + 대칭 정규화        │
│  → 변수 간 관계를 데이터에서 자동 학습        │
└────────────┬────────────────────────────────┘
             │
     ┌───────┼───────┐
     ▼       ▼       ▼
┌─────────────────────────────────────────────┐
│ GCN (Graph Convolution per Scale)           │
│  H' = ReLU(A_k · H · W)                    │
│  → 관련 있는 변수끼리 정보 교환              │
└────────────┬────────────────────────────────┘
             │
     ┌───────┼───────┐
     ▼       ▼       ▼
┌─────────────────────────────────────────────┐
│ Gated Fusion                                │
│  • 각 스케일을 T=2로 정렬                    │
│  • Softmax 게이트로 스케일 가중 합산          │
│  → 상황에 따라 중요한 시간 스케일 자동 선택    │
└────────────┬────────────────────────────────┘
             │
             ▼
┌─────────────────────────────────────────────┐
│ Dilated Causal TCN                          │
│  4 blocks, dilation = [1, 2, 4, 8]          │
│  + 잔차 연결 + Dropout(0.1)                  │
│  → 장기 시간 의존성 학습                      │
└────────────┬────────────────────────────────┘
             │
             ▼
┌─────────────────────────────────────────────┐
│ Regression Head                             │
│  AdaptiveAvgPool1d → FC → ReLU → FC → Sigmoid│
│  출력: normalized RUL ∈ [0, 1]              │
└─────────────────────────────────────────────┘
```

### 5.4 Adaptive Graph Learning (AGL)이 하는 일

기존 GNN은 그래프 구조(어떤 변수가 서로 관련 있는지)를 사전에 정의해야 한다. AGL은 이를 **자동으로 학습**한다:

1. 각 변수(노드)에 학습 가능한 임베딩 벡터 `E_nodes[i]`를 부여
2. 각 스케일에 스케일 임베딩 `E_scale[k]`를 부여
3. 둘을 결합하여 스케일별 특화 임베딩을 만들고, 이로부터 방향성 인접행렬을 생성:
   ```
   A_k = ReLU(M1·M2^T - M2·M1^T)   (비대칭 → 방향성 관계)
   ```
4. Top-K sparsification으로 가장 관계가 강한 K개 이웃만 남김 → 과적합 방지

→ 예를 들어, "CH1_BPFI_h1이 증가할 때 CH3_kurt도 함께 증가하는" 관계를 모델이 자동으로 발견한다.

## 6. 학습 전략

### 6.1 타겟 설계

각 시점의 타겟은 **정규화된 RUL**:

```
y_i = (전체 수명 - 현재 시간) / 전체 수명   ∈ [0, 1]
```

- 수명 시작: y ≈ 1.0
- 수명 종료: y ≈ 0.0

이렇게 정규화하면 수명이 다른 run들을 동일한 스케일로 학습할 수 있다.

### 6.2 손실 함수: Competition Score Loss

대회 평가 함수를 **직접 학습 손실로 변환**했다:

```
err = 100 × (y_true - y_pred) / y_true

  err ≤ 0 (과대예측, RUL을 길게 예측):  loss ∝ |err| / 20  ← 가혹한 페널티
  err > 0 (과소예측, RUL을 짧게 예측):  loss ∝  err  / 50  ← 완화된 페널티
```

**왜 과대예측에 더 엄격한가?**
실제 잔여수명보다 길게 예측하면, 정비 시점을 놓쳐 치명적인 고장으로 이어질 수 있기 때문이다. 반대로 짧게 예측하면 불필요하게 일찍 교체하게 되지만 안전 측면에서는 문제가 없다.

### 6.3 학습/검증 분할 — LOOCV

Train 데이터가 4개 run밖에 없으므로, **LOOCV(Leave-One-Out Cross Validation)**을 적용한다. 매 fold마다 1개 run을 완전 hold-out으로 제외하고 나머지 3개로 학습한다.

| 구분 | 방법 | 용도 |
| --- | --- | --- |
| LOOCV 4 fold | 매번 1개 run hold-out | 편향 없는 out-of-sample 성능 측정 |
| 최종 제출 모델 | 전체 4개 run 학습 | 실제 제출용 (late-life 25% 기준 체크포인트) |

- **LOOCV 체크포인트 기준**: 각 fold의 hold-out run 전체 구간에 대한 val_score 최대화
- **최종 모델 체크포인트 기준**: 전체 4개 run의 후반 25% 구간 late_score 최대화

### 6.4 학습 설정

| 항목 | 값 |
| --- | --- |
| Optimizer | Adam (lr=5e-4, weight_decay=1e-4) |
| Scheduler | Cosine Annealing (120 epochs) |
| Batch size | 32 |
| 윈도우 길이 | 16 프레임 (160분) |
| Gradient clipping | max norm = 5.0 |
| 정규화 | StandardScaler (각 fold 학습 데이터 기준) |
| Device | GPU (CUDA) |

## 7. 추론 (Inference)

### 7.1 과정

1. 테스트 베어링의 `.tdms` 파일들에서 동일한 특성 추출
2. 학습 시 저장한 scaler로 정규화
3. **마지막 16개 프레임**의 윈도우를 모델에 입력
4. 모델 출력(0~1 사이의 정규화된 RUL)을 실제 시간으로 변환

### 7.2 역정규화 (Denormalization)

```
RUL(분) = 모델 출력(ŷ) × 기준 수명(L_ref)
RUL(초) = RUL(분) × 60
```

여기서 **기준 수명 `L_ref`는 학습 데이터 수명의 중앙값**을 사용한다. 즉, 모델의 출력은 "평균적인 베어링 기준으로 남은 수명의 비율"로 해석된다.

### 8.2 Sanity Check — Out-of-Sample RUL 예측 결과

각 fold의 best 체크포인트를 해당 hold-out run에 적용한 **진정한 out-of-sample** 평가:

| Run | 파일 수 | 수명 | Mean Score | Late-25% Score | Last Score |
|---|---|---|---|---|---|
| Train1 | 126 | 1250 min | 0.472 | 0.164 | 0.000* |
| Train2 | 114 | 1130 min | 0.510 | 0.316 | 0.000* |
| Train3 | 89 | 880 min | 0.460 | 0.006 | 0.000* |
| Train4 | 137 | 1370 min | 0.461 | 0.398 | 0.000* |
| **평균** | | | **0.476** | **0.221** | **0.000** |

\* Last Score=0: `rul_true=0`(수명 종료 시점)에서 분모가 0이 되는 경계 케이스

**해석**:
- **Mean Score 0.476**: 전체 수명 구간에서 합리적인 out-of-sample 예측 수준
- **Late-25% Score 0.221**: 수명 말기 예측 성능이 낮음 — 특히 Train3(0.006)에서 두드러짐. Train3는 전체 run 중 수명이 가장 짧고(880분) 열화가 급격하여 3개 run으로 학습한 모델이 이 패턴을 일반화하기 어렵다
- Train4(0.398)가 late 성능이 가장 좋음 — 수명이 가장 길어 학습 데이터와 분포가 유사하기 때문으로 추정
- **LOOCV Mean 0.4931 vs Sanity Mean 0.476**: 비슷한 수준으로 일관성 있음

**최종 제출 모델** (`checkpoints/loocv/final/best.pt`)은 전체 4개 run으로 학습하므로, 실제 테스트 베어링에 대한 성능은 LOOCV 평균보다 높을 것으로 기대된다.
